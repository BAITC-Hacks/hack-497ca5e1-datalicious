# Интерфейс — разработчик 2

Реализован первый этап UI: обзор города, адаптивная тепловая таблица,
каталог 14 мер, фильтры, выбор районов и пяти решений, бюджет, причины
блокировки, синергии, ручное сохранение и восстановление localStorage.
Сохранённый сценарий проверяется перед восстановлением; версия датасета
входит в ключ. Неполный выбор сохраняется при переходе между экранами.

`ProjectShell` хранит сценарий и навигацию. `simulator/city-overview.tsx`
отображает исходные данные; `decision-builder.tsx` управляет выбором.

## Временные границы интеграции

- `baseline-fixture.ts` — явно обозначенная фикстура `ScoreSnapshot` из
  docs/DATASET.md для organizers-v1. Заменить на `engine.baseline()`.
- `selection-adapter.ts` — временный UI-адаптер публичного контракта
  `Pick<SimulationEngine, "validate">`. Проверяет черновики и возможность
  добавления меры по данным каталога. Заменить на доменный валидатор;
  при редактировании разрешать только ошибку недобора DECISION_COUNT.
- Формулы Score и расчёта эффектов здесь нет. Кнопка «Проверить сценарий»
  подтверждает комплектность выбора. Числовой результат и AI ещё не показаны.
- Следующий этап: подключить `evaluate`, экран результатов, Recharts и
  `/api/analyze` по общим типам. Не выдавать фикстуры за расчёт пользователя.

Интерактивные компоненты входят в клиентскую границу `ProjectShell`.
OpenAI и `src/server` в UI не импортируются. Данные, типы, API и конфиги не менялись.

## Проверка

`npm test` покрывает обзор, бюджет, выбор/удаление, фильтры, ограничения,
синергию, сохранение и повреждённое хранилище. Один `npm run test:smoke`
после build проверяет контрольный выбор, восстановление после перезагрузки,
адаптивность 320/390/768/1440 px и текущий API 501.
