# Правила разработки «Аким на 5 часов»

## Источники и границы

- Читать `docs/CASE.md`, `docs/DATASET.md`, `docs/ARCHITECTURE.md` перед реализацией.
- Исходные TXT — материалы организаторов; не переписывать автоматически.
- Правила: бюджет 100, ровно 5 мер, до 2 одного направления.
- Текущий этап — каркас; полные функции добавлять отдельными задачами.
- Общие типы только в `src/domain/types.ts`, без реализации.
- Данные неизменяемы, домен чистый, без React/Next/OpenAI/env.
- Формула только в домене, не дублировать в UI, API или промпте.
- Невалидный сценарий не получает Score. Критичность строго `<40`.
- Суммировать эффекты и синергии до clip; округлять только при отображении.

## Сервер и интерфейс

- SDK импортировать только в `src/server`; исполняемые серверные модули
  начинают с `import "server-only"`. Секреты без `NEXT_PUBLIC_`.
- SDK создаётся лениво; сборка и тесты без ключа и платных вызовов.
- Сервер валидирует JSON с Zod и повторно считает по исходному датасету.
- LLM объясняет факты, не рассчитывает Score и не заменяет числа.
- Проверять ответ LLM схемой, не раскрывать ключи и внутренние ошибки.
- Интерактивные компоненты и Recharts используют `"use client"`.
- Семантический HTML, подписи полей, управление клавиатурой.

## Совместная работа

- Зоны участников и ветки — в `docs/PLAN.md`.
- Общие контракты, конфиги, lock-файл менять согласованно небольшими PR.
- Использовать npm и `package-lock.json`, без другого менеджера пакетов.
- Сохранять чужие изменения, без force-push общей истории.
- Не коммитить `.env.local`, ключи, node_modules и отчёты тестов.
- Перед передачей: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
- Итоговый smoke: после build выполнить `npm run test:smoke`.
- Домен: граничные значения, лаги, синергии, конфликты, пример, отсутствие мутаций.
- AI: mock SDK. Отмечать невыполненные проверки и причины.
